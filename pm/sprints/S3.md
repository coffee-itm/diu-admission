# Sprint S3 — Auth & users (real accounts, real tokens)

Status: ✅ Ready to start · Phase: P2 (context/19) + S2 carry-over · Branch: `sprint/S3-auth` (from `prototype`) · Planned: 2026-11-08 by Opus

## Goal
1. **The server owns identity.** Register, login, refresh, logout and `me` run against Fastify + MongoDB with argon2id hashes, a 15-minute access JWT and a rotating refresh cookie with theft detection. RBAC guards exist and are proven by a matrix test. Admins can create reviewers and admins, and every write is audited.
2. **The SPA can talk to it.** `services/api.js`, react-query, and a `VITE_USE_MOCKS` switch so the offline demo keeps working. `authService` moves to the real API; the access token lives in memory only.
3. **Close the S2 carry-over**: the three QA findings, real coverage, and a CI run with zero annotations.

**This sprint kills D-22 (plaintext passwords)** — the oldest security defect in the register.

## Sprint notes

- **Planner decisions (Opus):**
  - *T-044:* my card told the builder to seed `PROGRAMS` from `src/lib/constants.js`, which would have made `server/` import the SPA and broken a server-only Docker image. `context/14` §3 + ADR-019 win: `PROGRAMS`, `ROLES` and `FACULTIES` moved to `@diu/shared`, SPA keeps a re-export shim. **Planner error — same class as the S2 retro item #2** (copy identifiers from the spec by grep, not from memory).
  - *T-045:* `fast-jwt` accepted in place of `@fastify/jwt` (`context/16` §2). Rationale: §5 specifies the token, not the library; `@fastify/jwt` is a Fastify decorator and a **pure, Fastify-free service is what §10 asks for**; `fast-jwt` is the library `@fastify/jwt` wraps, so tokens stay compatible. **T-046 must verify with the same library and secret**, and T-053 updates `context/16` §2.
  - *T-046 (owner rulings, 2026-11-08):* **FR-AUTH-01 phone regex widened** to `^(?:\+?880|0)?1[3-9]\d{8}$` — the original rejected the national `01XXXXXXXXX` form that nearly every BD user types, which would have blocked real registrations. **FR-AUTH-02 lockout now always returns the generic 401**; the 429 comes only from the per-IP limiter, because a 429 on the locking attempt revealed that an email is registered. Both amended in `context/13` (commit `a958040`).
  - *T-046:* **planner error.** My `context/13` amendment used a JS `String.replace` whose replacement text contained `$\``, which pasted the preceding half of the file into the row and truncated it from 192 to 132 lines. The builder caught it, restored from HEAD and re-applied the two edits cleanly. **Rule for the retro: never amend a spec with `String.replace` — the `$&`, `$\`` and `$'` patterns are live. Use an exact-text Edit.**
  - *T-046 (after review):* accepted the builder's `failedLogins.lastFailedAt` addition to `context/14` §3.2 — it documents a field FR-AUTH-02's "per 15 min" wording already requires, so it is a doc-catch-up, not a schema decision.
  - *T-046 (after review):* accepted the new one-row `loginTimingDecoy` collection as the way to equalise login-failure timing. **Follow-ups:** T-053 documents it in `context/14`; the P8 load test (S8) must check that this hot document does not serialise under a failed-login flood.
  - *T-045 (after review):* **sliding refresh expiry accepted for now** — an actively used token family never hits an absolute age limit. Safe given rotation + reuse detection, but an absolute family cap belongs in the P8 security review (S8, P8-01). Recorded there, not fixed here.
  - *T-045:* accepted four unspecified semantics the builder chose and documented: `revokeToken` revokes the whole family; refresh expiry slides on rotation; a missing/disabled user revokes the family; `pc` omitted when a reviewer has no program scope. All are safe-by-default readings.
