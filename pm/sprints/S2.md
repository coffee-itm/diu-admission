**The cheap tier needs more rounds but still wins**: a GPT-6 Luna build plus one fix round plus a Haiku review is far cheaper

builder's own log called ✅ — were:
1. **T-035:** `rs.initiate()` registered the replica-set member under the *container hostname*, so the documented host URI

   silent under-counting of anti-cheat risk.
3. **T-038:** `test:all` was `pnpm -r test`, which excludes the workspace root, so **CI would never have run the SPA's 225 tests.**
   (Caught at the coordinator gate, not by a reviewer.)

## Retro

**Went well**
- **Cross-family review earned its place.** Two of the three blockers were found by a reviewer from a different model family
  than the builder, by reproducing claims instead of reading logs. Mutation checks (break it, confirm a test fails, revert)
  found vacuous tests twice.
- **Pinning models per agent** removed an invisible Opus bill and made cost predictable.
- **`builder-lite` reading the card's own `Role:` line** worked — one cheap agent covered devops, frontend and docs cards
  with no prompt duplication.
- The documented **quota failover** was executed without improvisation when Codex ran out mid-T-040.

**Went wrong → changes to apply**
1. **Builders report ✅ on criteria they did not actually run** (3 occurrences). The playbook already forbids this for
   browser-only criteria; extend the rule to *anything requiring a running service* — if you did not run it in this session,
   it is `⚠️ not verified`. Add to `pm/AGENT_PLAYBOOK.md` step 6.
2. **Cards inherited spec errors.** T-036's card said `VALIDATION` where `context/15` says `VALIDATION_ERROR`; T-039's card
   implied a `classify` export that never existed. The planner must copy identifiers **from the spec by grep**, not from memory.
3. **Docs cards need the same evidence bar as code cards.** T-039 shipped 7 false claims first time. The docs-keeper rule
   "verify each claim with grep/ls" exists but was not enforced; make the reviewer's first action on a docs card be to
   re-check every factual assertion, which is what caught them.
4. **Monorepo scripts need an explicit "does it cover every package?" check.** `pnpm -r` excluding the root cost a near-miss.
   Add it to the devops role file.
5. **Codex quota is a real constraint**, not a theoretical one — it ran out after ~8 agent runs. Plan the cheap tier around it
   and expect to failover to Haiku 5.5 mid-sprint.
