## Retro
**Went well:** lanes plus the WIP limit of 3 kept agents off each other's files. Review → fix by resuming the same builder agent was cheap (it kept context). Opus re-reviewed the trivial fixes (T-009, T-011, T-020) itself instead of starting another reviewer.

**Went wrong → changes applied:**
1. **Parallel agents clobbered `BOARD.md`** (sed / full-file rewrites touched other rows; Summary counts went stale). Fix: the playbook now requires an exact-text Edit of your own row only, never the Summary, and builders never stage the board; the coordinator commits it.
2. **"None remain" criteria checked only the listed files** (T-011 missed LandingPage/admin Dashboard). Fix: the playbook says to prove such criteria with a repo-wide grep, and the card template tells the planner to list every grep hit under Files.
3. **Persisted-store changes ignored old localStorage state** (T-008, T-011). Fix: a new frontend-dev rule (backfill or `merge`/`migrate` + rehydrate test), and the card template prompts the planner.
4. **New lint warnings slipped in** (T-009) and a warning "owned" by T-004 was never removed. Fix: "No new lint warnings" is now in the gate and in the card template. The leftover warning is carried over.
5. **Builders marked browser-only criteria ✅ from code**, or left them unclear. Fix: these are marked `⚠️ not verified`, and the QA card verifies them (T-021 did, with agent-browser).
6. **Empty CSV columns shipped as a "follow-up"** (T-015). Fix: frontend-dev rule to join the data from the existing store or service.
7. A GateGuard hook blocked `git commit --amend`. Fix: the playbook now forbids amend outright, and review fixes are new `[T-xxx]` commits.
