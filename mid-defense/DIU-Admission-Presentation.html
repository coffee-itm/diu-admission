Background

Current challenges in DIU's admission process

  • 01
    GPA-Only Screening: Admission decisions rely solely on academic transcripts, missing domain-specific aptitude and potential.
  • 02
    No Standardized Assessment: Each department uses different criteria, creating inconsistency across the university's admission process.
  • 03
    Manual Processing: Paper-based tests and manual grading are slow, error-prone, and difficult to scale for thousands of applicants.
  • 04
    No Data Insights: No pre-enrollment data on incoming cohort quality, making it impossible to plan academic support.
Background

Objective

What this system aims to achieve

  • 01
    Unified Assessment: One university-wide digital admission test serving all departments and programs at DIU.
  • 02
    5-Competency Evaluation: Assess Math, Logic, IT, English, and Business aptitude in a single 54-minute session.
  • 03
    Automated Scoring: Instant, objective scoring with eligibility classification — eliminating manual grading errors.
  • 04
    Data-Driven Decisions: Section-wise analytics and merit lists to support transparent admission decisions.
  • 05
    Exam Integrity: Multi-layer anti-cheating system ensuring fair assessment for all candidates.
Objective

Expected Outcomes

Deliverables upon project completion

  • 01
    Fully Functional Web App: A responsive SPA with candidate portal, admin panel, and real-time test engine.
  • 02
    Automated Scoring Engine: Instant results with section-wise breakdown and 3-tier eligibility classification.
  • 03
    Analytics Dashboard: Interactive charts for pass rates, section averages, score trends, and cohort profiling.
  • 04
    Merit List Generation: Auto-ranked candidate list with eligibility badges and CSV/PDF export.
  • 05
    PDF Score Reports: Downloadable individual performance reports for candidates and admin records.

Quality attributes and constraints

    Scalability: Handle thousands of concurrent test-takers during peak admission windows.

    Response Time: Sub-second interactions for question navigation and answer submission.
  • 03
    Security: 7-layer anti-cheat system, input validation, and session isolation.

    Usability: Mobile-first responsive design (360px+), WCAG-compliant, bilingual-ready (EN/BN).

Stakeholders

Who interacts with the system

  • 01
    Admin (Admission Officer): Manages the entire system — question bank, exam configuration, candidate records, merit lists, and analytics. Full CRUD access to all modules.
  • 02
    Candidate (Applicant): Registers with program selection, reviews instructions, takes the timed assessment, and views results with downloadable PDF report.
  • 03
    University (Decision Makers): Uses analytics dashboards, pass rates, and merit lists to make data-driven admission decisions across all departments.

≥ 40% in every section

⚠️

Conditionally Eligible

≥ 40% overall but
< 40% in 1–2 sections

❌

Not Eligible

< 40% overall OR
< 40% in 3+ sections

Anti-Cheat System

7-Layer Protection

1

Tab-Switch Detection

Warning at 2 switches, auto-submit at 5

2

Fullscreen Enforcement

Exit detection with re-enter prompt, auto-submit at 3 exits

3

Clipboard Blocking

Copy, paste, and cut operations fully disabled

4

Right-Click Disabled

Context menu blocked and event logged

5

Keyboard Shortcut Blocking

Ctrl+C/V/A/P/S/U, F12, DevTools shortcuts

6

DevTools Detection

Window resize heuristic check every 3 seconds

7

Full Audit Trail

Every security event timestamped + per-question time tracking for admin review
